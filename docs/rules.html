深鲸守护 · CI 工作流安全 —— 6 条规则
 
[medium] CI-PR-TARGET
使用 pull_request_target 触发
依据：GitHub Docs — Events that trigger workflows: pull_request_target；GitHub Security Lab《Preventing pwn requests》
 
[high] CI-UNPINNED-ACTION
Action 未锁定版本（用 @main / @master）
依据：GitHub Docs — Security hardening for GitHub Actions: pinning to a full-length commit SHA
 
[high] CI-WRITE-ALL
workflow 权限设为 write-all
依据：GitHub Docs — Assigning permissions to jobs：最小权限原则
 
[high] CI-SECRET-ECHO
在 run 里直接输出 secrets
依据：GitHub Docs — Security hardening for GitHub Actions: 永远不要把 secrets 打印到日志
 
[high] CI-SCRIPT-INJECTION
run 里直接插值外部可控输入（脚本注入）
依据：GitHub Security Lab《Script injections in GitHub Actions》—— 攻击者可通过 PR 标题/分支名注入 shell 命令
 
[low] CI-NO-PERMISSIONS
workflow 未声明 permissions（继承仓库默认）
依据：GitHub Docs — Assigning permissions to jobs：未声明时继承仓库/组织默认，可能过宽
